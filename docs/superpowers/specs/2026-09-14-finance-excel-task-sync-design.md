# Finance Excel sheet synced with tasks

Date: 2026-09-14

## Goal

Раздел **Финансы** в NoteTask (`todo.baski.pro`) становится Excel-сеткой статей бюджета. Факт строки живёт от задач, ручных записей и платежей работы. Задача без явной статьи садится в статью с именем своего раздела (Здоровье, Работа, …), отдельно доход и расход.

## Current

- Sidebar: Сегодня / Финансы / История / Статистика + разделы-проекты.
- `#view-finance`: месяц, баланс, счета, таблица Статья · План · Факт · Δ, форма операции, журнал.
- Задачи: `cost`, `cost_type`, `project_id`. Категории бюджета нет.
- API: `GET /api/finance/sheet`, CRUD categories/accounts/transactions, `PUT /api/finance/budget/{ym}/{category_id}`.
- Факт месяца уже мешает задачи + ручные + работу, но без привязки задачи к статье.

## Decisions

- Сначала только Финансы. Раздел **Цели** (вкладки + игровой граф) — отдельный spec, не здесь.
- Строка = статья бюджета, не задача.
- Excel: клик-ячейка, Tab / Shift+Tab / Enter / Esc / стрелки, добавить/удалить строку. Формул нет.
- Страница: баланс + счета сверху; сетка снизу. Старые форма операции и журнал с страницы уходят. Журнал = клик по Факту.
- Факт = задачи + ручные записи + платежи работы этой статьи.
- Месяц задачи = `due_at`; нет срока — `created_at`.
- Статья по умолчанию = имя раздела (`projects.name`). Доход и расход одного раздела — **две** статьи (одна в группе Доходы, одна в Расходы), одно имя.
- Подход A: таксономия статей остаётся редактируемой; автомап только заполняет `finance_category_id`.

## Data

- `tasks.finance_category_id` INTEGER NULL, FK `finance_categories.id`.
- Категория уникальна в паре `(name, kind)` — «Здоровье» может быть дважды: `kind=income` и `kind=expense`.
- План как сейчас: `finance_budget(year_month, category_id, planned)`.
- Ручные `finance_transactions.category_id` без изменений.
- Платежи работы без своей категории → статья **Работа** / `kind=income` (создать, если нет). Расходные work-операции, если появятся, → **Работа** / `kind=expense`.

## Sync

1. **Создание/правка задачи** с суммой и без явного `finance_category_id`: найти категорию `name == project.name` и `kind == cost_type`; нет — создать в группе Доходы или Расходы. Нет `project_id` → имя «Без раздела».
2. **Смена раздела:** если PATCH/POST присылает `finance_category_id` — писать его. Если поля нет (или null) и есть сумма — перематчить по новому разделу. Отдельного флага «ручная статья» нет: клиент шлёт id, когда юзер выбрал статью сам.
3. **Факт статьи за месяц**  
   - задачи: `finance_category_id = cat`, `cost != 0`, месяц(`due_at` или `created_at`) = YM, `deleted_at` IS NULL  
   - ручные записи этой статьи в YM  
   - платежи работы, если статья — пара Работа+соответствующий kind  
   Факт строки одного kind: только источники того же знака. Доход и расход не смешиваются в одной строке.
4. **План** правится только ячейкой → `PUT` budget. Факт и Δ только считаются.
5. **Двусторонне:** правка `cost` / `cost_type` / `due_at` / категории у задачи сразу меняет Факт после reload sheet. Правка Факта в ячейке запрещена.

## UI

- Герой: месяц ‹ ›, баланс, доход/расход, чипы счетов — как сейчас.
- Сетка по группам. Колонки: **Статья | План | Факт | Δ | +**.
- Редактируемые ячейки: имя статьи, план. Клик → фокус, правка на месте.
- Клавиши: Tab / Shift+Tab по редактируемым; Enter — та же колонка, следующая строка; Esc — отмена; стрелки — выделение.
- Факт и Δ не инпуты. Клик Факт открывает ящик: список источников (задача / запись / работа). Клик задачи открывает её карточку.
- «+» в строке или в ящике: новая задача. Префилл: `finance_category_id`, `cost_type` = kind статьи, `project_id` если есть раздел с тем же именем. Спросить название и сумму.
- «+ строка» в группе: новая статья этого `kind`.
- Del на выбранной строке: пустая статья (план 0, нет проводок) — удалить; иначе отказ «сначала разнести».
- Мобилка ≤860px: тап + горизонтальный скролл сетки, без стрелок как основного ввода.

## API

Существующие маршруты остаются. Добавить/расширить:

- `GET /api/finance/sheet?year_month=YYYY-MM`  
  у каждой категории: `planned`, `actual`, `delta`, `fact_entries[]` (`source`: `task` | `sheet` | `work`, id, title, amount, day, task_id?).
- `POST/PATCH /api/tasks` — поле `finance_category_id`; автомап если null и есть `cost`.
- CRUD категорий как сейчас; создание с дублем `(name, kind)` → 409.
- `PUT /api/finance/budget/{year_month}/{category_id}` без изменений.
- Создание задачи из сетки = обычный `POST /api/tasks` с префиллом, отдельного finance-endpoint не нужно.

## Edge cases

- Повтор раздела: матч по точному имени проекта, первая категория нужного kind.
- Переименование статьи не переименовывает раздел. Уже проставленный `finance_category_id` остаётся.
- Переименование раздела: старые задачи держат id статьи; новые ищут по новому имени (новая пара статей, если нет).
- Recurring: одна живая строка, месяц = текущий `due_at` (как сегодняшний sheet).
- Удалить статью с проводками — 409.
- Бэкфилл при первом запросе sheet или одноразовый migrate: проставить `finance_category_id` всем задачам с `cost` по правилу автомапа.

## Tests

- Sheet: Факт статьи = задачи + ручные + работа; доход/расход одного раздела — две строки.
- Автомап: задача в «Здоровье» expense → статья Здоровье/expense; income → вторая.
- Смена раздела без явной статьи → новый id; с явной — не трогать.
- 409 на удаление непустой статьи и на дубль `(name, kind)`.
- Браузер: живые данные Турецкого/текущий месяц, **не** создавать новые суммы. Сетка, Tab, клик Факт, «+» задача (можно не сохранять).
