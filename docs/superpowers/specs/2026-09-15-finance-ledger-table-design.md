# Finance ledger table (replace budget grid)

Date: 2026-09-15

## Goal

Экран **Финансы** — Excel-таблица движений денег. Одна строка = задача с суммой или платёж рабочего проекта. Колонки как в Google Sheet пользователя, с маппингом «Проект» на раздел NoteTask.

## Current

- `#view-finance`: герой (месяц ‹ ›, баланс, счета) + сетка **Статья · План · Факт · Δ** + ящик Факта.
- Строка сетки = `finance_categories`. Факт = сумма задач / ручных txn / work payments за выбранный месяц.
- Задачи: `cost`, `cost_type`, `finance_category_id`, `project_id`, `due_at`.
- Платежи работы: `work_project_payments` (`planned` | `received`), живут в панели раздела Работа.
- Реальный Google Sheet пользователя — не бюджет, а реестр:

| Проект (в Sheet) | Направление | Цена | Месяц | Статус |
|---|---|---|---|---|
| Спортики | CRM | +255 000 | 31.08.2026 | Подтверждено |
| Спортики | Манаков | −50 000 | 31.08.2026 | Подтверждено |
| Снеговоики | Снеговики | +250 000 | 30.09.2026 | Подтверждено |
| … | Cursor / Еда / Дом / … | ± | конец месяца | Подтверждено |

Итог Sheet 551 000 в UI **не** показываем (герой достаточно).

## Decisions

- Подход A: **реестр поверх существующих сущностей**, без таблицы `finance_ledger`.
- Сетка Статья/План/Факт/Δ **выключается**. Таблицы категорий/бюджета в БД не дропаем.
- Строка = задача с `cost != 0` **или** платёж работы.
- Колонка **Проект** = имя раздела (`projects.name`): Работа, Личные дела, Покупки, Здоровье… — любой раздел, где есть сумма. Не Спортики/Снеговоики/Жизнь/Кредитка.
- Импорт/понимание старого Sheet: Спортики и Снеговоики → **Работа**; Жизнь и Кредитка → **Личные дела**. Направление остаётся title (CRM, Манаков, Cursor, Еда, Дом…).
- **Направление** = `tasks.title`; у платежа работы = `work_projects.name`.
- **Цена** = signed RUB. Задача: `+cost` если `cost_type=income`, иначе `−cost`. Платёж работы: `+amount` (доход).
- **Месяц** = реальная дата: `due_at` задачи, `paid_at` платежа. Не принудительный конец месяца. Пустая дата — пустая ячейка, строка всё равно в таблице.
- **Статус**: задача `open` → «План», `done` → «Подтверждено». Платёж `planned` → «План», `received` → «Подтверждено». Смена статуса в таблице = complete/reopen задачи или PATCH статуса платежа.
- Все месяцы в одной таблице. Фильтр — шапка колонки, как Excel (уникальные значения + галочки).
- Герой: доход / расход / баланс = сумма **видимых** (после фильтра) строк. Стрелок месяца нет. Чипы счетов как сейчас (остатки счетов, не из фильтра).
- Правка inline: клик, Tab / Shift+Tab / Enter / стрелки, `+` строка, Delete. Итоговой строки нет.
- `+` строка = локальный черновик в UI (не POST). Дефолт: раздел Личные дела, статус План, дата сегодня, title «Новая строка». `POST /api/tasks` когда Цена ≠ 0. Фейковые суммы вроде 0.01 запрещены.
- Delete выделенной строки = удалить задачу или платёж (существующие DELETE).
- Строка платежа работы: **Проект** всегда «Работа», не меняется. Можно править направление (work project), сумму, дату, статус.
- Повторы (Cursor сентябрь и октябрь) — не особая логика: две задачи = две строки. Recurring не размножаем по месяцам.
- Ручные `finance_transactions` и категории в эту таблицу **не** входят (пока не просили).
- Живые суммы при verify не выдумывать.

## Data / API

Новый endpoint, старые sheet-маршруты остаются для счетов и внутренних нужд.

`GET /api/finance/ledger`

Ответ:

```json
{
  "rows": [
    {
      "source": "task",
      "id": 174,
      "project_id": 2,
      "project_name": "Личные дела",
      "title": "Cursor",
      "amount": -20000,
      "day": "2026-09-30",
      "status": "plan"
    },
    {
      "source": "work",
      "id": 12,
      "work_project_id": 3,
      "project_id": 4,
      "project_name": "Работа",
      "title": "Снеговики",
      "amount": 250000,
      "day": "2026-08-20",
      "status": "confirmed"
    }
  ]
}
```

- `status` в API: `plan` | `confirmed` (UI: План / Подтверждено).
- Состав `rows`: все неудалённые задачи с `cost IS NOT NULL AND cost != 0`; все платежи живых work-проектов.
- Сортировка по умолчанию: `day` DESC, nulls last, затем id DESC.
- Summary на сервере не обязателен: герой считает клиент по видимым строкам.
- Фильтры Excel — клиент. Датасет личный, без пагинации.

Запись — существующие API, без новых PATCH-ledger:

| Ячейка | Task | Work payment |
|---|---|---|
| Проект | `PATCH /api/tasks/{id}` `{ project_id }` | нет (зафиксировано Работа) |
| Направление | `{ title }` | `{ work_project_id }` (select существующих work_projects, без rename в ячейке) |
| Цена | `{ cost: abs, cost_type: income\|expense }` по знаку | `{ amount }` (всегда ≥ 0) |
| Месяц | `{ due_at }` (дата; время 00:00 если не было) | `{ paid_at }` |
| Статус | complete / reopen (тот же путь, что «Выполнить») | `{ status: planned\|received }` |

`POST /api/tasks` для `+` строки — только когда черновик получил ненулевую Цену: `{ title, project_id, cost, cost_type, due_at }` (`status` open). Title пустой → `"Новая строка"` (уникалить 2, 3… среди черновиков и живых задач).

`DELETE /api/tasks/{id}` / существующий DELETE платежа.

`finance_category_id` автомап можно оставить в backend (не мешает); UI категорий не показывает.

## UI

1. Герой: три числа (доход+, расход−, баланс) по **отфильтрованным** строкам + чипы счетов. Без ‹ › месяца.
2. Таблица: **Проект · Направление · Цена · Месяц · Статус**.
3. Шапка колонки: кнопка фильтра → список уникальных значений + «Выделить все» / снять. Несколько колонок — AND.
4. Ячейки:
   - Проект: `<select>` разделов.
   - Направление: текст (contenteditable или input).
   - Цена: число, формат `−20 000` / `255 000`.
   - Месяц: `input type="date"`.
   - Статус: select План / Подтверждено.
5. Клавиши только внутри таблицы: Tab по ячейкам, Enter — вниз та же колонка, стрелки — выделение, Esc — blur, Delete/Backspace на выделенной строке (не когда фокус в input) → удалить.
6. Кнопка `+ строка` под таблицей: сразу видна пустая строка-черновик; POST после первой ненулевой Цены.
7. Строки `source=work`: select Проект disabled; Направление = select work_projects.
8. Мобилка ≤860px: горизонтальный скролл таблицы, фильтры доступны тапом по шапке.
9. Убрать: бюджетные таблицы, `+ строка` категории, ящик Факта, форму операции (уже убрана).

## Edge cases

- Задача без раздела: Проект пустой / «Без раздела»; `+` строка так не создаёт (дефолт Личные дела).
- Цена `0` после правки: строка пропадает с реестра (нет суммы) — ок, задача остаётся в Сегодня.
- Смена знака цены меняет `cost_type`, `abs(cost)` пишется в `cost`.
- Work amount в таблице нельзя сделать отрицательным: минус игнор или clamp ≥ 0 + alert.
- Complete recurring задачи: одна живая строка, дата = новый `due_at` (как сейчас complete). Историю месяцев не клонируем.
- Пустой `due_at`: фильтр Месяц имеет значение «(пусто)».
- 409/ошибка PATCH: alert `detail`, ячейка откат к старому значению.
- Личные дела fin-panel (месячная сводка) **не** часть этого spec — не ломать, не переписывать.

## Tests

- Ledger: задача expense/income и work payment попадают разными `source`; знаки суммы верные.
- Open task → `status=plan`; done → `confirmed`; planned payment → `plan`; received → `confirmed`.
- Задача без cost не в `rows`.
- PATCH статуса через существующий complete не тестировать заново целиком — хватит маппинга в ledger helper.
- Браузер: Финансы открывается; нет сетки Статья/План/Факт; есть 5 колонок; фильтр колонки прячет строки и меняет герой; `+` строка (можно не сохранять деньги); не создавать новые живые суммы.

## Out of scope

- Формулы, копипаст, протяжка, итог 551 000.
- Импорт Google Sheet в живую БД (маппинг Спортики→Работа только для понимания/будущего импорта).
- Раздел Цели / игровой граф.
- Live-sync Google Sheet.
- Дроп `finance_categories` / `finance_budget` / `finance_transactions`.
- Менять `finance_months` в панели Личные дела.
